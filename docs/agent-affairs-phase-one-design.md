# 千问事务录入：第一阶段设计

日期：2026-10-04。分支：develop。状态：范围已确认；本文待用户审核，尚未进入产品代码实施。

## 1. 用户目标与边界

用户希望在首页对 Agent 说一段包含多件事情的话，千问识别主线、项目、行动或待整理内容，展示可以修改的预览，用户确认后写入现有事务模块，不再逐个打开手工表单。

第一版支持新建收集记录、主线、项目、行动，以及预览中选择复用已有主线或项目。保留现有财务录入，不重设计首页、工作台和收集箱。采用现有千问服务端配置、publishable key、Auth cookie 和 RLS。

不支持修改或删除旧记录、自动完成、记录进展、修改关注项目、自动生成阶段成果、金币或奖励操作、计时、通知或到点提醒。长期“核心事情”不等于奖励金币的核心行动。模型不能直接调用数据库。

本阶段不新增数据库表、字段、RPC，也不执行 migration。新建操作走已部署的四个创建 RPC。保持收集箱一条记录只能整理为一个目标的规则；首页多项录入不是对一个收集项做一对多整理。

## 2. 现有代码核对

- `src/lib/agent/qwen.ts` 只解析财务，已有服务端千问调用、结构化输出及错误映射。
- `schema.ts`、`orchestrator.ts`、`confirm.ts` 和 `src/app/agent-actions.ts` 当前只处理财务预览及确认。
- `AgentWorkspace` 已有首页对话及交易预览，不存在事务解析或事务预览。
- `create_affairs_mainline`、`create_affairs_project`、`create_affairs_task` 接受 `p_request_id` 与 typed payload；`create_affairs_inbox_entry` 接受 `p_request_id` 与原文。已有 owner 隔离、数据库命令回执及幂等重放。
- 项目必须有 `outcome`，主线不需要；行动仅有 `project_id`，没有直接的 `mainline_id`。
- 项目/行动只有 `due_date`，不是日历预约或提醒；行动说明可以保留具体日期时间。
- `AffairsDatabaseError` 区分明确拒绝与未知提交结果。根布局已经挂载事务导航保护，但首页预览需要主动接入 dirty/pending/unresolved 标记及离开保护。

## 3. 路径选择

三种实现路径：

1. 只让模型拆分并存入收集箱：改动少，但用户仍要逐条整理，不能满足本次直接录入主线和行动的目标。
2. 复用现有创建 RPC，预览后逐项确认/依赖排序保存：推荐。无需数据库部署，真实结果可见，沿用现有幂等能力。
3. 新建整批原子 RPC：可实现整批回滚，但需要新数据库协议及 migration，扩大本阶段范围。

采用路径 2。“确认保存全部”是按依赖顺序执行多个独立原子 RPC，不是整批原子事务。若中途失败，已成功项目不撤销，不用删除记录模拟回滚。

## 4. 首页识别与域隔离

保留一个自然语言输入框，不要求用户先选择财务/事务模式。

先用一个轻量、严格结构化的千问请求，只判断 `finance / affairs / mixed / unsupported`，输入只有用户文字，不提供任何数据库候选或凭据。随后：

- finance：调用现有财务解释器及确认链路，不改变金额、预算和交易口径。
- affairs：用同一个已认证 SSR client 并发读取真实主线和项目，再调用独立事务解释器；不读取或发送账户余额、交易、金币或奖励信息。
- mixed：第一版提示将财务和事务分别发送，不生成任何可确认卡片，不执行写入。不让一句混合指令静默漏掉其中一类。
- unsupported：明确告知未支持，原文留在对话，不自动存入收集箱。

正常识别需要两次模型请求（分类 + 对应领域解析），有额外识别延迟；配置复用，不新增模型供应商、API Key 或环境变量。两阶段均有超时/格式校验，分类失败不能默认走财务。服务端错误消息不暴露原始 provider 返回、密钥或数据库详情。

首页反馈从“正在识别交易”改为“正在整理内容”。财务解释结果与事务解释结果采用带 domain 的类型边界，原有财务 schema 和确认函数保持独立。

## 5. 事务解释契约与服务端校验

输入：用户原文、当前上海日期时间、真实可选主线和项目的 ID/名称/状态及项目所属主线。仅发送匹配所需字段，不发送已有描述、任务历史或其他模块数据。

输出：短说明、按原文顺序排列的 items、无法识别的原文片段。一次最多 20 项，原文最多 4000 个 Unicode 字符，超出限制拒绝，不截断或静默丢弃。

每项含：类型、原文片段、拟用名称/标题、说明、成果、日期、原文明确表达的上海时间，以及父级关联建议。不适用字段必须为空。收集项保存明确要求收集的原文；无法理解的片段仅显示未识别，不能自动持久化。

模型不生成 RPC 名、requestId、数据库创建 ID、owner、状态、金币、排序、就绪状态或 SQL。schema 禁止额外字段；服务端生成 draftId/requestId，并根据校验结果计算 ready/needs_input。原文片段必须能对应输入，不能接受模型编造的“用户要求”；无法对应的项不允许确认。

父级引用分为：真实已有 ID、本批拟新建目标的临时引用、未指定。服务端检查资源种类、真实用户可见性、引用唯一性及依赖无环；临时引用不能伪装成 UUID。新项目只可关联主线，新行动只可关联项目。生成执行计划时拓扑排序，同一层仍保持原文顺序。

验证规则：

- 名称/标题 1–200 字，项目成果 1–2000 字，说明不超过既有 RPC 限制，收集原文 1–4000 字；超长不截断。
- 不编造项目成果或行动完成条件。明确项目缺少成果时卡片需要用户补充，不能猜一个成果并标为可保存。
- 行动默认普通、未完成、无截止日期；项目/主线使用既有 RPC 创建默认状态，不自动成为关注项目。
- 只有用户明确要求具体行动为核心，且明确提供目标和完成条件时，才允许预览核心资格。用户也可在卡片里主动勾选并补齐两字段。仅说“核心做的事情”不会将四条主线转换为四个核心行动。
- 日期按 Asia/Shanghai 解释，允许未来计划；不得复用财务“不能在未来”的校验。有效日期必须是真实日历日期。
- 无年份的月日按当前上海年份显示在预览，并标注年份为推断；跨年或歧义要求用户确认/修改，不擅自滚动到下一年。没有年份、明确时间等不确定性不能隐藏。
- 明确预约日期映射到 due_date 时，预览标为“计划日期（保存到截止日期字段）”；具体时间保留为说明中的“计划时间：YYYY-MM-DD HH:mm（Asia/Shanghai）”，可同时出现在行动标题。没有新提醒功能，不声称这是日历事件。
- 明确预约时间保留结构化预览字段，由服务端确定性写入说明，不能只靠模型自由文本避免遗漏；日期修改后必须同步时间对应日期，清空日期不能暗中保留旧时间。只有日期没有时间时不编造时间。
- 已归档主线不可作为新项目的父级，已完成/归档项目不可作为新行动的父级。失效候选显示需重新选择，不自动套用关注项目。

## 6. 复用、归属与重复处理

唯一精确同名的现有主线/项目可以作为“复用已有”候选，预览明确展示真实名称与归属。语义相似、别名、重名、归档候选均只能提示用户选择，不默默修改、复用或重建。

例如“搭建系统”与已有“打造并持久运行个人系统”属于语义匹配，应显示建议复用、需要确认，而不是假定两个名字相等。选择复用不会更新旧说明、状态或产生创建 RPC。

已有同名行动只能提示可能重复，不自动完成或覆盖；需要用户选择跳过或仍然新建。解析后按拟用标题执行 owner/RLS 下的定向候选读取（最多 20 个标题，读取 ID、标题、状态、所属项目，不加载全量任务或历史，不把这些结果发送给模型）。用户修改标题或项目后重新核对候选，过期结果不得更新新卡片。并发设备新建同名记录仍可能出现重复，第一版不声称全局名称唯一。真正的同一次提交重复通过现有 requestId 解决。

行动无法直接归属“找工作”主线。若没有明确项目，预览显示“独立行动 / 未关联项目”；提供真实项目选择，并允许用户明确添加项目卡片。不能自动编造“10 月招聘与面试”。未指定父级本身合法，不强制所有行动先有项目。

移除/跳过被引用的父级卡片时，关联的子项变为需重新选择归属，禁止悬空引用或悄悄改成独立行动。可以明确选择解除关联后再保存。

## 7. 预览交互

在现有暗色首页对话中新增独立事务预览组件，不改其他模块布局。

每张卡片显示原文对应片段、类型、名称、归属、日期时间及缺少字段。支持直接修改、选择复用、跳过、按需创建父级；字段复用事务表单的数据校验，不复制隐含业务口径。核心字段折叠/按需出现，不把所有字段铺满卡片。

未开始写入前可随时编辑。只要选中项有字段错误、依赖冲突或尚未确认的匹配，整个“确认保存全部”按钮不可用；跳过不完整项后可以保存剩余合法项，按钮明确显示选中数量。

第一次确认后冻结选中项、requestId、规范化 payload、排序及引用关系。保存中和结果未知时，禁用修改、跳过、重新识别、再次启动其他批次或离开；重试使用冻结的原提交。预览组件不能因 router.refresh 或屏幕尺寸改变而重建提交标识。

逐项状态：待保存、保存中、已保存、已复用、明确失败、结果未知、因父级未完成而等待。真实成功回执显示查看行动/项目/收集项链接；主线链接到工作台。没有 optimistic fake data。

明确失败可重试同一内容；要修改失败内容，需先结束原批次并保留已保存清单，仅对明确未执行/被拒绝的项创建新预览和 requestId。结果未知项不能走此入口。

浏览器前进/后退、页面内导航、关闭预览和关闭页面均接入保护。浏览器关闭/强制刷新无法完全阻止，第一版不持久化客户端批次；必须显示“结果未知时先核对记录，不要重新发送”的提示，不宣称跨刷新自动恢复或恰好一次录入。

## 8. 确认保存数据流

客户端按冻结计划串行调用单项 Server Action，一次请求只执行一个创建 RPC，避免 20 项一起占用单次服务端执行窗口。复用项经过认证读取核对，不调用写 RPC。

每项 Server Action：

1. 建立 SSR client，使用 getClaims 验证当前用户。
2. 严格解析允许的 DTO，不能信任模型或客户端的 ready 标志。
3. 对选中 payload 做与手动录入同口径校验；引用既有对象或先前已保存父级实际回执 ID，不接受其他用户资源。
4. 转为明确白名单命令，调用 foundation-mutations 或 inbox-mutations。白名单仅四个 create；不得把客户端提供的 arbitrary operation 传给通用 submitAffairsAction。
5. 成功返回真实 AffairsReceipt，revalidate `/affairs` layout。刷新失败仍属保存成功，提示手动刷新，不能重新创建。

单项结果未知就暂停整个执行队列；不得继续启动其他写入。明确失败也暂停，未执行子项保持等待。之前成功项保留回执，不再创建；重试未知项使用相同 requestId 和相同 payload，由 RPC 幂等重放返回原对象。

对于已启动的请求，不能因关联对象后来被归档或改名，就在应用层挡住对原请求的幂等核对。参数格式/身份校验仍执行；新写入的状态/owner 限制由现有 RPC 验证，重放遵循现有 RPC 合约。不能将未知父级换成新 ID后重试子项。

客户端不得使用 Promise.all 并行执行整批写入；候选读取可以并发。没有数据库记录写入前不更新金币、热力图或工作台计数。本阶段创建记录本身不会产生金币或推进贡献。

## 10. 用户示例验收

原文：10 月 8 日早上 10 点半星璇智能面试；10 月 18 日下午 1 点国安双选会；核心做的事情是搭建系统、准备国考、找工作、写大论文。

在测试固定上海时间 2026-10-04、候选含“打造并持久运行个人系统”时，应有六件明确事项的预览：

- 两个普通行动，分别显示 2026-10-08 10:30、2026-10-18 13:00，年份推断可见，具体时间最终保留。
- 四条主线意图。“搭建系统”提示复用已有主线，须确认；其余三条是否新建取决于实际候选及用户预览选择。
- 没有已确认项目时，两行动为独立行动；可在预览中关联真实项目，不自动创建额外项目。
- “核心”没有给具体行动的完成条件，不自动赋予核心金币资格。
- 解析、编辑、复用预览均不写库，确认才写入，确认后工作台可看到真实记录。

同时验证：显式项目缺少成果、多个可能匹配对象、日期无效、无时间、跨年歧义、明确收集、未知内容、财务/事务混合、prompt injection、伪造 ID、跨用户 ID、依赖循环、删除父项后的悬空引用。

## 11. 验证与发布门槛

单元测试覆盖分类/schema/provider失败、日期时间无损映射、候选和归属、核心资格、超长输入、所有不支持操作的拒绝。服务测试证明：解析不写库；确认只走白名单 RPC；同 requestId 重试不改 payload；父项回执 ID 正确传递；遇到未知/失败暂停；成功后刷新失败不视作未保存。

交互测试覆盖：编辑和跳过、缺少字段阻止批次、语义匹配必须确认、真实候选不可用、pending/unknown 锁定、刷新和 responsive 不重建未知命令、离开保护、逐项真实结果及链接。完整测试、typecheck、lint、build 通过后再做浏览器桌面/手机验收，并回归现有财务 Agent。

正式库联调只录入用户明确确认的真实事项；不得偷偷插入测试记录，模型实测只生成预览也不得点击保存。涉及向千问发送的内容为用户的明确输入和上述最小候选上下文。生产发布另需用户授权，届时复用已配置的服务端环境变量。
