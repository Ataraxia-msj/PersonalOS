# 事务工作台：精简热力图、日历与甘特图

日期：2026-10-04。状态：方向已确认，书面设计待审核，尚未实施。按本仓库事务设计文档惯例保存在 `docs/`，不放入已忽略的 `docs/superpowers/`。

## 1. 目标与已确认范围

用户希望减少无关文字占位，并从同一套事务中查看待办、日期安排和项目跨度。用户作息及可用时间不固定；本功能不要求预留固定时间块，不把时间安排作为完成任务或获得金币的条件。

已确认：

- 删除热力图上方的「推进轨迹」「近半年 · 全部主线」及下方的「如何阅读」，保留热力图、月份、星期、当天标识和点击当天查看真实记录。
- 工作台提供紧凑的「清单｜日历｜甘特」切换，不为新视图建立重复的任务数据。
- 日历展示行动日期及时间、项目截止日期；无日期内容仍可找到。
- 甘特图按主线、项目、行动组织；仅有真实起止日期时显示跨度。
- 补充可选的计划开始日期、结构化时间字段，保持当前暗色设计及移动端可读性。
- 继续直接在 develop 开发；数据库 migration 文件、应用实施和生产发布分开验收。此设计文档本身不授权执行正式库 SQL 或再次发布。

## 2. 现状与方案选择

仓库核对结果：

- `affairs_projects`、`affairs_tasks` 已有 `due_date`，没有计划开始日期或独立钟点字段。
- 首页 Agent 的 `plannedTime` 当前通过 `toAffairsConfirmation()` 写入说明，不进入独立列。
- 手动创建/编辑和收集箱整理共用 metadata 校验；数据库基础 RPC、收集箱 RPC 都需要扩展。
- 工作台 service 已并发查询主线、项目、行动、推进、贡献和金币；新视图可复用这批读取。
- `vw_affairs_project_progress` 定义包含 `p.*` 及三个进度字段；替换 View 必须保留已有输出列名称、类型和顺序，新字段追加到尾部。
- RPC 命令记录按 owner + request_id 比较规范化 payload，不能因新字段默认 null 改变旧命令的比较结果。

选择：扩展现有项目和行动字段，在同一工作台切换三种视图。

其他方案不采用：

1. 仅用截止日期做前端时间线：可以展示节点，但不能满足真正的跨度式甘特图。
2. 新建独立日程/日历事件子系统：会重复录入面试等事务，引入额外关联、同步和删除语义，当前没有必要。

第一版自建日期网格与时间轴组件，使用现有 React/CSS，不引入大型日历或甘特依赖。其代价是第一版不提供拖拽、依赖连线或日内周视图。

## 3. 时间字段与业务含义

在 `affairs_projects` 和 `affairs_tasks` 各增加两个 nullable 字段：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `planned_start_date` | `date` | 用户明确设置的计划开始日期 |
| `planned_time` | `time without time zone` | `due_date` 当天的约定/截止钟点，固定上海时间，精确到分钟 |

`due_date` 继续作为现有行动日期或项目截止日期，不新增一份重复的结束日期。主线不新增排期字段。

规则：

- 日期全部可选；仅开始日期、仅截止日期和两者都空均合法。
- 起止同时存在时，`planned_start_date <= due_date`；同一天合法。
- `planned_time` 非空必须有 `due_date`。有效值为 00:00–23:59，不允许 24:00、秒或隐含的默认钟点。
- 时间始终附着于 `due_date`，不是跨度开始当天的时间。对于单日面试，两字段即面试日期与钟点。
- 不推断会议长度，不添加默认一小时，不把未填写时间的事项当作午夜预约。
- 创建时间、完成时间、首次推进时间都不能代替计划开始日期。
- 创建和修改均在服务端校验，并由 SQL 约束/校验再次保证；非法范围不截断、不自动调换。
- 数据库读取的 time 字符串允许标准的 `HH:mm:ss`，adapter 在秒为 00 时转为 UI `HH:mm`。异常非零秒或不合法值报告字段问题，不能静默舍去。

示例：面试填日期 2026-10-08、时间 10:30，开始日期可空；论文项目填开始日期 2026-10-01、截止日期 2026-12-20，时间可空。两者均不要求每天预约学习时段。

## 4. 数据库与旧请求兼容

提供一个新的增量 migration，不编辑已经执行的历史 migration，不删除表、行或命令历史。

涉及内容：

1. 两张表增加 nullable 列和日期/分钟精度约束，原记录保留新列 null。
2. 扩展 `affairs_private.metadata` 的字段白名单、类型与日期时间校验。
3. 更新 `affairs_private.foundation` 的项目、行动创建与修改分支，保持其他分支、锁顺序、owner 校验、revision、核心资格和金币口径不变。
4. 更新 `affairs_private.resolve_inbox`，使整理为项目/行动的创建也写入时间字段。
5. 以显式旧列列表替换 `vw_affairs_project_progress`，原列顺序保持不变，新列追加；保留 `security_invoker=true` 和 authenticated SELECT。
6. RPC 公共签名、回执结构、authenticated 权限不变；private 函数仍不能由客户端直接调用，不增加 anon 权限或直接表写入权限。

兼容要求：

- 旧创建 payload 未包含新字段时，新列为 null。
- metadata 仅在输入实际包含某个新字段时，将该新字段放入规范化 payload；绝不能为所有旧 payload 自动补新键。这保证旧命令原 UUID + 原 payload 的幂等回执仍可读取。
- 新客户端创建/编辑必须显式提交新字段（含 null），使清空操作有确定含义；参数类型接受旧客户端不含新字段的 DTO。
- 旧客户端更新未提供新字段时，保留已有开始日期和时间；但旧更新清空 `due_date` 时，同时清空其附属 `planned_time`，避免无日期时间。开始日期可单独保留。
- 对新更新最终有效状态做校验：显式 null 是清空，缺省是兼容保留。旧客户端将截止日期改到已有开始日期之前时拒绝，不能偷偷删除开始日期。
- 幂等回执检查仍先于新写入的引用、状态和最终范围校验；已提交的旧请求即使对象后来改变，仍返回原回执。
- 清空截止日期的新表单同时清空时间；客户端拒绝显式提交「无日期 + 非空时间」。
- 不修改 `affairs_commands` 的历史 payload、回执或 revision。

旧说明中的时间不批量解析和回填：普通备注与旧 Agent 文本不能一概当作排期。保留原说明，旧记录按已有日期展示；用户在编辑页补一次结构化时间后显示钟点。此边界必须在交付说明中明确，不宣称旧钟点已自动迁移。

migration 前检查已部署函数/View 的定义和字段，若与仓库对应定义不一致，停止并报告差异，不以仓库假设覆盖未知线上变更。正式库验收只读，不自动写入测试事项或金币。

## 5. 工作台布局与状态

从上到下：事务导航与新增入口、数据总览、无标题热力图、紧凑视图工具栏、当前视图。

工具栏以视图切换为主要控件，复用行动范围（全部、独立、主线、项目）；日期控件只在日历/甘特出现。默认清单，不额外加入大标题、教学段落或永久图例。可访问名称用 aria 属性保留，不占视觉空间。

- 清单：保留现有主线/项目结构与行动清单。
- 日历：日历及所选日详情，代替重复的主线树和行动列表。
- 甘特：分层左列和时间轴，代替重复的主线树和行动列表。

范围在三种视图间保持一致。默认展示当前未完成行动及 active/paused 项目；已完成与归档通过紧凑筛选开启，取消行动在当前视图默认隐藏。核心/等待筛选应用于行动，项目仅作为其组织上下文，不在这种筛选下额外显示无关项目日程。独立行动不因无主线而被隐藏。

URL 保存 `view=list|calendar|gantt`、`month=YYYY-MM` 及范围选项；缺省视图是 list、月份是服务端提供的上海当前月。非法参数安全回到缺省，不接受参数直接形成数据库查询字符串。

切视图、月份、范围和浏览器前进/后退遵守现有未保存/未知结果保护：dirty 状态离开须确认；pending/unknown 不允许隐藏表单或换视图，原请求和回执保留。不通过复制 task data 制造保存状态。

## 6. 日历交互

桌面端默认月视图，星期一开头，显示完整周，提供上个月、今天、下个月；无自动预约或弹窗提醒。

- 有 `due_date` 的行动显示在对应日，有 `planned_time` 则显示真实钟点，否则作为无钟点事项。
- 有起止日期的行动以跨日日期范围展示，结束当日可显示实际填写的钟点；只有开始日期时显示开始节点，不延伸到今天。
- 项目有起止日期时展示计划范围，只有截止日期时展示截止标记，只有开始日期时展示开始标记。
- 日期范围两端包含当天，跨月事项裁剪在网格内，但详情保留完整起止日期。
- 完全无日期的事项放在「未安排 · N」折叠清单，仍可以直接打开编辑。
- 某天过多事项显示有限条目和「+N」，点击展开当天完整清单；排序稳定，含钟点的当日事项按时间排序。
- 点击事项显示现有真实名称、所属项目、日期、时间、状态和编辑入口。使用现有编辑页，不做一套新写入 API；已完成/已归档内容仍遵守原有编辑限制，不因新视图获得额外写权限。
- 点击空白日期打开现有新增行动表单并预填日期；仍需用户点击保存，读取页面或点选日期不写入。
- 无数据时保留可操作网格与新增入口，不生成示例日程。

手机端展示紧凑日期选择与所选日清单，不挤入七列密集文字。月切换和未安排入口仍可用；切换视口不重建编辑请求。

## 7. 甘特图交互与真实口径

左侧按照「主线 → 项目 → 行动」排列；另有独立项目、独立行动分组。无项目的主线可以折叠，不为其创建虚构条目。项目可展开/收起，事项点击后走日历相同的详情/编辑入口。

第一版时间轴以所选月为窗口，显示日期与周分隔、今天线、上月/今天/下月；不提供多种缩放档位。

- 同时有起止日期：实心计划条，按真实日期位置及包含首尾当天的跨度绘制。
- 同日开始结束：最小可点击的一日条，不是假造工时。
- 只有截止日期：截止节点；只有开始日期：开始节点，两者均不延长为条。
- 无日期：左列标记「未安排」，时间轴留空，提供设置日期入口。
- 时间窗口外的事项保留左列信息与超出方向提示；跨窗口条裁剪，点击仍显示完整范围。
- 主线仅是分组标题，不显示虚构主线进度或跨度。未排期项目的子行动即使有日期，也不自动写成项目排期。
- 项目进度仍读取 `vw_affairs_project_progress.progress_rate`，null 显示未知；不按日期流逝、行动数或子项跨度重算完成度。
- 行动展示真实状态，不给进行中行动生成任意百分比；条长表示计划日期跨度而非累计投入。
- 明确区分未来、今天、已逾期未完成事项，不因为到期自动变更状态或扣金币。

手机端只有甘特时间轴容器横向滚动，名称列可保持可见；整页不横向溢出。所有可点击条/节点有键盘入口与完整 accessible label，不能只靠颜色区分状态。

第一版无拖拽排期、依赖关系、关键路径、自动调整父子日期、重复任务、提醒或外部日历同步。

## 8. 前后端数据流与组件边界

读取：Server Component → Affairs service → typed queries → SSR Supabase client（经 Auth 验证）→ adapters → 纯日期投影函数 → 清单/日历/甘特组件。

- 继续复用工作台已有查询，同一页面不为每个视图再次查询同一套项目和行动。
- 页面和组件中不散落 `.from()`；查询错误显示错误/重试，不能假装空列表。
- 将共用范围筛选、上海日期运算、月网格和时间轴映射独立为纯函数；三个视图引用同一真实记录 ID。
- 日期运算不依赖用户设备时区；date-only 用日历日期计算，不用浏览器本地午夜混合 UTC。
- 日期选择引起的纯前端投影不需要写入、不新增缓存，不改变金币/财务业务。
- 复用已有分页读层，不把 Supabase 默认返回上限误当作完整结果。

保存：现有表单/Agent 预览 → server action → metadata 验证 → 现有 atomic RPC → 真实回执 → revalidate/refresh。成功后清单、日历、甘特反映同一记录；失败不替换真实 data，结果未知沿用原 UUID 和冻结 payload 重试。

需要改动的主要位置：

- `supabase/migrations/`：增量排期 migration；`supabase/checks/` 与 `supabase/tests/`：结构、权限、幂等和约束验证。
- `src/lib/affairs/types.ts`、`validation.ts`、`inbox-validation.ts`、`adapters.ts` 及 Supabase 类型：扩展 metadata/row 与兼容处理。
- `src/features/affairs/components/entity-fields.tsx`：创建、编辑、收集箱整理共用日期时间字段；`context.ts` 等入口上下文处理预填日期。
- `src/lib/agent/affairs/` 及 Agent preview：让已有 `plannedTime` 真正写入 `planned_time`；增加可选开始日期识别、编辑和校验，禁止凭空推断开始日期。
- `src/features/affairs/`：独立 schedule model/纯函数、视图工具栏、日历、甘特、详情面板；精简 heatmap 并接入工作台。
- 对应单元测试、页面/交互测试与使用说明。

Agent 新模型字段兼容旧客户端 DTO，unknown frozen 请求不因字段升级变化。未给年份的开始/截止日期均必须确认；相对日期沿用已修复的上海日期规则。保存后时间字段成为日历唯一钟点来源，旧说明只作原始上下文，不再是计算来源。

## 9. 验收与发布顺序

验收至少覆盖：

1. 三处占位文案不再可见，热力图点击和 accessible label 保留。
2. 月初/月末、闰日、跨年、周一开头、跨月条、只有一个端点、完全无日期、午夜/23:59 时间与设备非上海时区。
3. 主线/项目/独立行动范围切换；归档、已完成、取消、核心、等待的真实可见性。
4. 页面有空状态、查询错误和字段错误区别；无 mock fallback。
5. 创建、编辑、收集箱整理和 Agent 四入口都保存/读取真实新字段；清空日期/时间、非法跨度等前后端一致。
6. migration 前创建的命令在升级后仍可原 UUID 原 payload replay；参数变化冲突仍拒绝，revision stale 仍拒绝，旧更新不丢失新排期字段。
7. 新字段不改变金币余额、核心完成资格、任务状态或财务数据；其他 RPC 分支保留原行为。
8. 视图切换/前进后退不会丢失 dirty/pending/unknown 操作；保存后不显示 optimistic fake data。
9. 桌面与约 390px 移动端可读，日历/甘特节点能点击并打开真实记录，甘特局部滚动而非整页溢出，无框架报错或相关 console error。
10. `npm run test`、`npm run typecheck`、`npm run lint`、`npm run build` 通过。

上线顺序：完成 migration 文件及验证 → 用户在正式库执行 migration 并确认 → 核对新字段/View/权限 → 前端验证通过后再授权合并 main 和 Vercel 发布。数据库先扩展兼容旧应用，前端不可先上线查询尚不存在的列。不新增环境变量，不索要密码/secret/service_role。

本轮设计阶段只创建此文档；尚未删改 UI，尚未生成/执行 migration，尚未更改正式站点。
