## 你现在需要做的第一步

打开 [部署前只读核对 SQL](../supabase/checks/affairs_schedule_preflight.sql)，复制完整内容，在现有 Supabase 项目的 SQL Editor 执行。复制返回的单个 `report` JSON 单元格（或导出 JSON 文件）发回来。不需要密码、secret 或数据库连接串。

先核对真实库的三个私有函数、项目进度 View、列顺序、RLS 和权限与仓库是否一致；有差异先报告，不覆盖未知定义。

## 核对通过后

1. 由你执行 [排期迁移](../supabase/migrations/202610050001_affairs_schedule.sql)，不要重复执行。迁移包含结构/函数冲突保护和单事务回滚。
2. 执行 [部署后只读核对](../supabase/checks/affairs_schedule_postflight.sql)，发回单个 `report` JSON。预期项目表、行动表、项目 View 合计出现 6 个排期字段，两个 schedule 约束存在，`invalid_rows` 均为 0，原 RLS/security_invoker/权限保留。
3. 然后验收本地真实数据，最后另行授权合并/推送/Vercel 发布。不要先发布依赖新列的前端。

不要在正式库运行 `supabase/tests/`；这些脚本会创建/写入一次性测试环境，本轮只在本地内存数据库运行过。

## 排期与阅读

- 工作台默认「清单」，点击「日历」查看月历。上月、下月、今天和浏览器前后退同步 URL；切月不重新查询。
- 手动新增/编辑、统一新增、收集箱整理、Agent 预览共用结构化排期。在「更多选项」设置开始日期、截止日期及时间。
- 单个日期表示当天事项；两个日期表示包含两端的范围；都没有进入「未安排」。父项目和子行动排期彼此独立，不自动推算。
- 时间是截止日期当天的上海钟点，不是时长，支持 00:00–23:59。无截止日期不能设置时间，清空截止日期也清空时间。
- 月历无主线、周视图或独立甘特入口；主线关系仍在清单和项目管理中。
- 点击项目/行动打开完整详情和编辑入口。手机点击日期看完整当日清单；`+N` 展开全部事项。
- 点击空白日期只预填新建行动的日期，仍须显式保存；手机在当日清单点击「新增行动」。

旧说明里的“10:30”等文字不会自动回填。打开旧记录编辑一次，将日期/时间填入对应控件并保存即可。
