# 事务工作台：月历融合项目跨度

日期：2026-10-04。状态：用户已选定参考图及功能方向；本书面设计待审核，尚未修改产品代码或数据库。替代 `affairs-calendar-gantt-design.md`。直接在 develop 开发。

## 1. 选定视觉与目标

选定本轮第一张参考图：`assets/affairs/month-calendar-selected.png`。沿用现有暖暗色、橙色强调及顶部导航；示例事项、数字和热力图只作视觉参考，产品必须读取真实数据。图片中个别横条端点不准确，实际代码以真实日期及下述规则为准。

用户要在同一个月历中看项目推进跨度、可完成的 TODO 和面试等零散事件，而非强制预约每天的时间块。

- 工作台只保留「清单｜日历」；日历仅有月视图，不提供周视图或独立甘特入口。
- 日历不展示主线标题、主线侧栏、主线层级或主线筛选；主线仍存在于原有清单和项目管理数据中，不删除其关联。
- 取消热力图的「推进轨迹」「近半年 · 全部主线」「如何阅读」。保留真实热力图、日期标签、当天标识和查看当天记录的能力，压缩高度。
- 保留真实数据总览、顶部统一新增入口，不添加大标题、说明段落或永久图例。
- 全宽月历展示项目横条、TODO 复选入口、零散事件时间点；未安排内容仍可访问。
- 不增加提醒、重复事项、拖拽、依赖关系、工时、外部日历同步或新金币规则。

## 2. 数据现状与最小扩展

仓库中项目、行动已有 `due_date`，尚无 `planned_start_date`、`planned_time`。Agent 已识别的 `plannedTime` 当前写入说明，不能作为日历可靠字段。项目 View 是 `vw_affairs_project_progress`；工作台 service 已并发读取项目、行动等数据并分页读取完整结果。

在 `affairs_projects`、`affairs_tasks` 各追加 nullable 列：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `planned_start_date` | date | 明确设置的计划开始日期 |
| `planned_time` | time without time zone | `due_date` 当天的具体钟点，固定 Asia/Shanghai，分钟精度 |

沿用 `due_date` 作为结束/截止日期。日期可全部为空或只有一个端点；两端都有时开始不晚于结束，首尾当天均包含。钟点必须有截止日期，只接受 00:00–23:59，不接受秒或 24:00。服务端和数据库都校验。

不得将创建、完成、推进时间作为开始日期；不得从自由文本自动推断或批量回填钟点。旧事项保留原说明，未补结构化时间前只显示已有日期。读取标准 `HH:mm:00` 转为 `HH:mm`，异常秒值报错，不静默丢弃。

## 3. 项目、TODO 和零散事件的含义

不新增独立事件表，也不引入未经批准的事件类型列：已有项目仍为项目，TODO 和零散事件均引用现有行动记录。无项目的行动不被隐藏；有项目的面试也可以显示钟点。不能仅凭是否关联项目将一条记录判定为会议或取消其完成能力。

所有行动均沿用真实状态及现有完成操作，保留可完成入口；钟点事项增加时间点标记，TODO 增加复选入口，两者不是互斥业务类型。钟点属于排期信息，不自动将任务变为会议、不代表时长，也不改变任务是否可完成。普通零散事务即使无钟点，也可在对应日期显示并完成。

主线字段不进入月历投影和详情展示。任务详情可显示所属项目；项目详情编辑仍沿用原功能。

## 4. 月历投影和布局

- 星期一开头，显示覆盖所选月份的完整周，可能 4、5 或 6 周；上海服务端日期确定今天和默认月份。
- 工具栏只有清单/日历、月份、上月、今天、下月，不添加类型筛选；保留原清单自己的筛选，日历不会继承隐藏主线范围。
- 默认日历展示 active/paused 项目与 todo/in_progress/waiting 行动；已完成、归档、取消默认不展示。点击完成成功后该 TODO 从默认月历移除，完成记录仍在现有历史和真实热力图中。
- 项目有完整起止日期时显示连续横条；跨周拆成延续片段，跨月裁剪到网格。片段共用记录 ID，不能重复统计。
- 行动有完整起止日期时也显示日期范围；只有截止日期时放在当天，只有开始日期时放在开始当天，不能自动延伸到今天。
- 单端点项目显示当天项目标记，不伪造横条；两端全空进入「未安排 · N」。项目和行动各自排期，不能用子行动日期自动补父项目跨度。
- 横条长度表示日期范围，不表示全天占用或完成进度；条内不显示百分比。
- TODO 有可点击复选入口及标题；零散事件有小标记、标题和实际填写的钟点。无钟点不显示默认午夜，不虚构结束时间。
- 每周范围条由稳定排序分配不重叠的轨道；当天条目按真实钟点、类型、名称、ID 稳定排序。日历投影为纯函数，不包含数据库写入。
- 当天事项过多时提供「+N」展开完整当日清单，不丢记录或重叠文字。未安排折叠清单可打开真实详情/编辑。
- 月历详情按需出现，不永久占一列；无主线信息或无关说明。可显示名称、项目、完整起止日期、时间、状态及编辑入口。
- 移动端保留七列日期选择，范围概要及所选日可读清单，不将所有长标题挤入小格；仍是月视图，不出现周模式，整页不横向溢出。

## 6. 数据库及旧客户端兼容

只新增增量 migration，不修改已执行 migration，不修改历史命令。更新私有 metadata、foundation、resolve_inbox 的项目/行动路径；不改变公共 RPC 签名、锁顺序、Auth、RLS、owner/revision 校验或金币口径。

- 旧 payload 缺少新键时，规范化 payload 也不得自动补新键，以保证历史命令原 UUID 和原 payload 的幂等 replay。
- 旧创建的新列为空；旧更新缺省新键保留已有新字段。旧更新清空截止日期时清空附属钟点，不能偷偷清空开始日期以放过非法范围。
- 新客户端显式提交新键，null 代表清空；校验最终有效状态。
- 已提交命令的回执检查先于变化后引用和状态校验；原命令即使对象后来变化仍返回原回执。
- 项目进度 View 用显式旧列顺序保持已有列名和类型，将新列追加到末尾；保留 security_invoker 及 authenticated SELECT。
- 不增加 anon 权限、表直接写入权限或 secret/service_role。
- 编写只读 preflight/postflight，migration 前核对线上真实字段/函数/View；若与仓库不同，报告差异，不用假设覆盖未知定义。正式库不自动写入测试事项。

## 7. 文件和数据流边界

读取：Server Component → Affairs service → typed queries → Supabase SSR client → adapters → 纯日期投影 → 月历。复用已有工作台项目和行动查询，不为切月份重复查询 View，不在组件散落 `.from()`。

保存：现有表单/收集箱/Agent 预览 → server action 校验 → 现有 atomic RPC → 真实回执 → refresh/revalidate。四个录入入口同步支持结构化开始日期和钟点；不为日历创建重复记录。

主要文件：

- `supabase/migrations/`、`supabase/checks/`、`supabase/tests/`：增量排期字段与兼容验证。
- `src/lib/affairs/types.ts`、`validation.ts`、`inbox-validation.ts`、`adapters.ts`、Supabase types：字段与校验。
- `src/features/affairs/types.ts`、`components/entity-fields.tsx`：真实 UI model 与共用日期表单。
- `src/lib/agent/affairs/`、相关 Agent preview：保存真实时间及可选开始日期，不改 unknown 请求。
- `src/features/affairs/schedule.ts` 与月历组件/样式、`progress-dashboard.tsx`、`contribution-heatmap.tsx`：纯投影、视图切换、热力图精简。
- 现有上下文/导航保护：支持 `view=list|calendar`、`month=YYYY-MM` 和预填日期；非法参数回到默认，不直接拼数据库字符串。清单仍默认入口。

查询失败显示错误/重试，不伪装空列表；没有数据保留空网格和新增入口，不回退 mock。无需新增环境变量。
