# 转账操作说明

## 上线顺序

1. 确认正式库已执行 `supabase/migrations/202609080003_transfer_transactions.sql`。若已成功执行，不要重复运行。不要执行 tests/fixtures。
2. 再发布前端。用户已于 2026-09-08 确认迁移执行成功并批准发布；发布不会再次执行数据库迁移，也不向正式库提交测试交易。
3. 在一笔真实资金移动发生后，由用户记账核对。此页面只记录账本，不实际操作银行或钱包转账。

## 如何记账

财务 → 新增交易 → 转账，选择用途、北京时间、金额、转出/转入账户和描述。

- 普通转账：资产账户间调拨，不计收支或预算。资金转回也用此项。
- 储蓄 / 投资：资产账户间移动，只展示对应用途的真实预算分类。按累计投入计入，不因普通转回减少；再次投入会再次累计。
- 还款：资产账户 → 负债账户，只记本金，减少欠款；费用和利息另记支出。

仅允许本人不同的同币种账户。不根据账户名称猜用途，不做汇率换算。显示的账户余额是估算值，不作为余额不足时的记账限制。沿用不补录/修改余额校准时点之前交易的操作约定。

未指定分类仍可记录，但不占预算，且本阶段不支持补改转账归属。指定分类但尚未建月预算时，归属先保存，之后保存该月预算自动归集。关闭月份不改变；缺 allocation / 币种不同会明确提示。所有这些 warning 都是交易事实已成功保存，不能重复记账。

## 网络异常和重复提交

提交前在当前标签页的 sessionStorage 保存一次请求 UUID 和原始表单内容（不含认证凭据）。保存失败时不发送 RPC。只有明确成功或确认本次没有写入时才清理匹配的恢复记录。

网络结果未知时保留原请求、锁定内容，点击「重试同一次转账」；不会自动重放，也不会生成另一个 UUID。刷新或在同一标签页离开再返回可以恢复原请求。后续重试失败不能证明首次未写入，因此继续保留。旧请求迟到不能清除新请求的恢复信息。

不要在另一个标签页重复新建，不要清除浏览器存储；关闭标签页可能丢失恢复信息。需要重新登录时可在新标签页登录后返回原标签重试。若原标签已丢失，先核对交易记录，再决定是否重新记账。

## 读取与兼容

- 概览、交易页使用 `vw_transaction_details`，分页读取全部 confirmed 明细后按 entry_id 分组。
- 转账显示一笔移动金额、实际账户方向和用途，不把两行相加、不显示为收入。
- 币种来自同时读取的 `vw_account_balances(account_id,currency)`，包含历史停用账户。这是币种校验所需读取，不是为账户筛选额外串行查询。
- 账户筛选从完整交易明细生成，任一账户都能找到同一笔交易。
- 历史未知格式不猜方向/合计金额，可展开「原始明细」查看账户、带符号金额及备注；不开放编辑。
- 新普通转账/储蓄/投资/还款暂不支持编辑、删除、作废；原单行 expense 编辑能力不变。
- 预算/分析只解释累计投入口径，不修改既有汇总公式，不使用 mock fallback。
