执行后运行只读 `supabase/checks/affairs_inbox_postflight.sql`：确认表的 owner SELECT RLS、五个 RPC 的 authenticated EXECUTE、anon/public 不可调用、客户端不可直接写表、私有 helper 空 search_path。

前端已在 develop；未自动合并、推送或部署。新表未部署时，导航收集箱数量显示“—”，收集箱显示短错误，原项目/商店/账本可继续使用。

## 使用

- 任意事务页点击“＋新增”，默认只收集原文；也可直接创建行动、项目、主线，或记录进展。
- 工作台：真实四项统计 → 推进轨迹 → 主线与全部项目 → 默认所有未完成行动。项目展开可看到其行动，独立行动在全局清单中。完整清单保留已完成、已取消及操作历史。
- 收集箱：待整理 / 已整理 / 已丢弃。选中一条后整理为一个行动或一个项目；不会自动指定核心资格、日期、关注项目或阶段成果。
- 原文保留在收集记录和新目标说明中。标题超过 200 字需显式缩短，不截断原文。行动默认普通、无项目、无截止日期；核心行动须明确目标与完成条件。
- 待整理记录可编辑原文或丢弃；丢弃后可恢复。已整理记录不可重复整理或恢复，只查看原文和真实目标。目标改名/归档不改变来源链接。
- 未保存切换需确认放弃。保存中、提交结果未知时不可关闭或切换；重试保持同一请求标识与内容，防止重复创建。
- 在项目详情打开“新增 → 行动”时预填当前可用项目；项目失效则明确提示重新选择，不自动套用关注项目。创建成功后切换创建类型会重新读取选项，重新打开入口也会刷新选项。
- 浏览器前进/后退受事务表单保护；其他操作刷新导致行动状态变化时，尚未确认结果的完成请求仍保留原版本与重试入口。手机来源链接直接打开抽屉，切换屏幕尺寸不会重建整理请求。
- 收集、整理、编辑、丢弃和恢复不产生金币或推进贡献。核心完成仍走既有奖励 RPC。

## 统计口径

待办包含 todo / in_progress / waiting，普通、核心、独立和需恢复所属项目的行动均计入；进行中项目仅 active。近 7 天完成按上海当天及之前 6 天的真实 completed_at、当前 done 计一次，重开不计、未来时间不计。金币余额读取现有 View，允许负数。阶段百分比读取真实项目 View，缺值显示“—”。

## 安全与验收

publishable key + Auth cookie + RLS，无 secret/service_role、无数据库密码。新操作必须通过五个原子 RPC；一条收集项只能整理为一个目标。幂等、版本冲突、owner 隔离和失败回滚已在隔离 PGlite 验证。

真实写入联调须待用户执行 migration 后，以明确指定的测试条目进行；目前未在正式库创建测试数据。真正双会话并发脚本仅允许 `personal_os_affairs_isolated_test`，不能在正式库执行。
